# Contributing

Thank you for your interest in contributing to NOpenNLP.

To contribute to this repo, please:
1. Make sure there is an open issue for the feature, bug fix, or chore/task you want to do. If not, open one!
2. Ask to have the issue assigned to you. We usually will, but may do the work ourselves in certain cases depending on urgency, importance, or complexity.
3. Fork our repo, if you haven't yet. Make sure to review the license to ensure you are able and willing to contribute code under this license.
4. Create a new branch off the `main` branch (make sure your fork is up to date first), i.e. `issue/123` with the issue number. (This is not required, but can help you find it later.)
5. Implement the feature/bug/task on your branch.
   Make sure you test building and running tests in the repo before submitting your PR, to help reduce rework cycles.
   When committing, if your work was done with AI assistance, please make sure it includes your agent as a co-author.
   Do not include external code without permission from a maintainer, which may only be given after reviewing the license of the work.
6. Open a PR targeting `main` from your branch. 
   Give the PR a clear title that references the issue number, i.e. "Port the XYZ namespace, #123".
   Give the PR a description of what was done, and any special notes for reviewers.
   Note that it "Fixes #123" if the PR should close the issue when merged.
   If your PR was generated using AI assistance, please give it proper attribution in the description.
7. Stand by for PR review comments or suggestions, and kindly fix them promptly.
   In some cases, we may make the changes for you, if you enable edits by maintainers.
   If we do this, it is not to diminish or take away from your PR (you'll still retain primary credit); it would merely be to reduce feedback cycle time.
